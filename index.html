TECHNICAL BENEFITS

Security • Architecture • Performance

Security

  • No user accounts, logins, or personal data collection
  • Secure, one-time access code for session entry
  • End-to-end browser-level encryption via WebRTC
  • Access code validated at host level
  • No public rooms or persistent sessions
  • No recordings, no storage, no cloud backups

Architecture

  • Fully peer-to-peer (P2P) media transmission
  • Video, audio, and screen data never touch servers
  • Backend server used only for connection signaling
  • Hosted using Netlify (frontend) and Render (signaling)
  • Uses Google STUN for secure peer discovery

Performance

  • Browser-based — no installation required
  • Low-latency real-time visual transmission
  • Multi-platform: Laptop Sharing & Mobile Camera
  • Zero server media bandwidth consumption
  • Reduced server lag due to P2P architecture

SYSTEM CONSTRAINTS

Network & Connectivity

Network Restrictions

  • Corporate Wi-Fi/VPNs often block STUN/ICE relays.
  • Firewalls may prevent peer discovery in strict environments.
  • Switching to public networks usually resolves connection issues.

Mobile Limitations

  • Mobile browsers cannot share system screens or audio.
  • Only Direct Camera and Microphone relay is supported.
  • For full screen-sharing, use a desktop/laptop browser.

Cold Start Delays

  • Initial P2P handshakes take 10-60s to stabilize.
  • Black screens are normal during the synchronization phase.
  • Wait at least 1 minute before declaring a connection failure.

MISSION PROTOCOL

User Guide

Connection Flow

  • 1. Viewer First: Must click "Establish Connection" before the Host.
  • 2. Security Handshake: This viewer-first sequence is an intentional security feature.
  • 3. Sync: System synchronizes relay points during the handshake.
  • 4. Host: "Begin Transmission" unlocks ONLY after viewer is ready.
  • 5. Ready: Host clicks to start mission.

Host Rules

  • Transmission is blocked until viewer initiates.
  • This prevents unauthorized or blind sharing.
  • Handshake takes 10-60s (protocol behavior).
  • Use Smart Controls to manage Mic/Cam.

Viewer Rules

  • Must be the one to start the flow.
  • Await host stream after Establishment.
  • Full-screen mode blocks Duo requests.

Duo Mode

  • Optional 2-way voice collaboration.
  • Viewer must accept the voice link.
  • Share specifics tabs to avoid echo.
